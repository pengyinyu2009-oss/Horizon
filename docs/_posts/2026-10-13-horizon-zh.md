### *（简报）* [将 WiFi 7 路由器改造为 320 Msps 软件定义无线电接收机](https://github.com/h0m3us3r/w1700k-sdr) ⭐️ 7.0/10 · 相关 8/10

一个开源项目对 Gemtek W1700K WiFi 7 路由器内部的 MediaTek MT7996 射频芯片进行了逆向工程，用自定义固件替换原厂程序，将其改造为一台宽带软件定义无线电接收机。该设备可在 2.4/5/6 GHz 频段以最高 320 Msps 的速率采集 14 位 IQ 采样数据，并通过 10 GbE 以太网使用零拷贝 UDP 协议实时传输到 Linux 主机。 该项目大幅降低了宽带 5 GHz 软件定义无线电的入门门槛，无需专用 SDR 板卡即可实现，使用普通消费级路由器硬件即可达成。它还展示了一套可复用的模板，用于改造现代 WiFi 6E/7 射频 SoC，为在其他消费设备上进行类似改造打开了大门。 逆向工程是对联发科固件逐寄存器进行的，并非简单地复用驱动代码。该方案目前仅支持 2.4/5/6 GHz ISM/WiFi 频段的接收功能，主机端的频谱和瀑布图渲染需要在 Linux 上运行。

<a id="item-3"></a>
### *（简报）* [Python 3.15 正式发布：引入显式延迟导入与解包推导式](https://simonwillison.net/2026/Oct/12/python-3-15/) ⭐️ 7.0/10 · 相关 3/10

Python 3.15 正式发布，其中最值得关注的新特性是 PEP 810 引入的显式延迟导入（explicit lazy imports），开发者可以用 `lazy` 关键字标记导入语句，让模块在实际被使用时才加载。该版本还引入了 PEP 798 推导式中的解包语法；同时 Python 3.10 已停止维护，库维护者现在可以放心地使用 3.11 及更高版本的语法。 显式延迟导入直击 Python 长期存在的痛点——模块加载时导入重型依赖导致的启动缓慢，对 CLI 工具、测试套件以及基于插件的应用尤其有价值。随着 3.10 退出支持，Python 社区终于可以在不写兼容代码的前提下使用 `tomllib`、`Self` 类型注解、精细化错误位置以及 `except*` 等较新语法。 延迟导入使用一个占位符对象，在第一次访问时才解析为真正的模块，因此只需在现有 `import` 语句前加 `lazy` 关键字即可完成迁移，改动量极小。推导式中的解包语法（`[*L for L in lists]`）本质是额外嵌套一层 `for` 子句的语法糖，并未改变语义，且支持列表、集合与字典推导式。

<a id="item-4"></a>
### *（简报）* [循环复用 Transformer 块：Looped Diffusion Transformer 减少约 4.9 倍推理算力](https://www.reddit.com/r/MachineLearning/comments/1x49d61/looped_diffusion_transformer_the_same_blocks_run/) ⭐️ 7.0/10 · 相关 4/10

研究人员提出 Looped Diffusion Transformer，在每个去噪步内将同一组 Transformer 块循环复用多次，而不是简单地扩大模型规模。论文报告 2.6 亿参数的循环模型在多项基准上击败了体型大 6.5 倍的 DiT，同时推理算力减少约 4.9 倍，代码与权重以 MIT 协议开源，权重发布在 Hugging Face 的 sensenova 账号下。 这项工作挑战了 DiT 类文生图模型默认的"一味堆参数"路线，证明在每个去噪步内循环复用同一组块，比直接加深网络更参数和算力高效。由于循环深度可在采样时自由调节，用户可以在不重新训练的前提下按需用推理时间换取图像质量，这对在消费级硬件上跑文生图模型具有现实意义。 单纯的循环复用训练不稳定，因此作者在每次循环迭代上都加了深度监督，并设计了自调制注意力机制来稳定训练。提交者在 M5 Pro 上用 PyTorch MPS（fp32、100 步 Euler、CFG=6.0）复现了 B/16 变体，发现大部分质量提升在 depth 3 之前就已经出现，depth 3 与 depth 4 的图像几乎一致；单张图的推理延迟大约从 depth 1 的 23–24 秒翻倍到 depth 4 的 43–47 秒。
