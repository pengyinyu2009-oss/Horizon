## [ESP32 Wi-Fi 射频被破解，可变身软件定义无线电](https://hackaday.com/2026/10/15/so-you-want-to-make-your-sdr-work-on-other-frequencies/) ⭐️ 7.0/10 · 相关 8/10

**干啥的**: 这篇 Hackaday 报道介绍了硬件社区近期最热的话题之一——多个团队独立发现 ESP32 内置 Wi-Fi 射频的隐藏 SDR 模式：通过修改固件让 Wi-Fi 硬件绕过协议栈直接输出原始 IQ 基带采样，从而把一块几美元的 ESP32 开发板变成一台简易软件定义无线电接收机。

**亮点**:
- 多家团队独立完成逆向验证，说明该能力是硅片层面固化的，并非单个工程样品的偶然行为
- 把 SDR 实验的硬件成本从 RTL-SDR 加密狗（约 25 美元）压缩到 ESP32 开发板（最低不到 5 美元），并具备更低的功耗
- 可以直接对接 RTL-SDR、GNU Radio 等成熟开源 SDR 工具链，复用社区多年来积累的解调和协议分析代码
- 同时涉及射频逆向、固件改写、信号处理三个领域，是硬件开发者练习全栈技能的好项目

**我的判断**: 这个项目非常值得动手复刻，特别适合预算有限的电子工程师和硬件开发者作为入门 SDR 与 RF 逆向的练手项目。文档目前以社区博客和论坛为主，完整度依赖后续贡献者；整体复刻难度中等，需要熟悉 ESP32 工具链、能够解读原始 IQ 流，并大概率要配合外置低噪放或下变频器才能用到 2.4 GHz 之外的频段。它最适合已经具备 MCU 调试经验、对射频有兴趣的学习者；如果你只是想在 Windows 上接一根天线就收听常见广播，RTL-SDR 仍是更省心、文档更完整的成熟选择。

rss · Hackaday · 10月15日 14:00

**背景**: 软件定义无线电（SDR）用数字信号处理替代传统模拟射频电路，使同一硬件仅靠切换软件就能接收多种无线协议。ESP32 是上海乐鑫（Espressif）推出的低成本 Wi-Fi/蓝牙微控制器，在物联网项目中应用非常广泛。基于 RTL2832 芯片的 RTL-SDR 加密狗长期是业余 SDR 玩家的入门选择，而基于 ESP32 的 SDR 方案可以更便宜、更省电，只是其 2.4 GHz 射频的覆盖范围比宽带 SDR 窄得多。

**对中国影响**: ESP32 由总部位于上海的乐鑫（Espressif）设计并大规模量产，因此这一发现凸显出中国设计的 MCU 自带未公开的 RF 能力，正在被全球开源硬件社区积极挖掘。它也再次印证了中国低成本芯片在全球创客生态中的战略价值。

**对我有什么用**: 对于电子工程师或硬件开发者来说，这是一个非常值得动手复刻的周末项目：拿一块 5 美元的 ESP32 开发板烧写社区固件，不必购买专用 SDR 加密狗就能拿到原始 IQ 采样，正好可以借机温习射频基础、信号处理和 ESP32 固件逆向技能。

### *（简报）* [追踪中国独居石垄断：稀土背后的放射性代价](https://spectrum.ieee.org/china-rare-earth-minerals) ⭐️ 6.0/10 · 相关 3/10

**干啥的**：本文是 IEEE Spectrum 与《Foreign Policy》合作发布的调查报道，系统梳理了中国内蒙古包头稀土加工产业（尤其是独居石 monazite 的处理）的崛起历史、环境代价以及由此形成的全球稀土供应链垄断格局。

**亮点**：
- 以占地约 10 平方公里的尾矿坝（Weikuang Dam）为切入点，揭示中国稀土加工数十年累积的剧毒与放射性污染（钍）。
- 详细介绍白云鄂博矿——世界最大稀土矿床，去年产出约 17 万吨稀土金属——其以氟碳铈矿（bastnaesite）为主、独居石为伴生矿的开采模式，解释中国禁止"单独开采独居石"的法规逻辑。
- 指出镝、铽、钇、铒等关键稀土元素高度依赖独居石矿源，而这些元素正是高性能电机与永磁体的核心材料。
- 报道欧美及亚洲国家斥巨资重塑稀土供应链却仍把独居石视为替代矿源，警示这些国家将不可避免地遭遇钍废物治理挑战。

**我的判断**：从项目/技术视角来看，这篇报道并不适合也不值得"复刻"，因为它本身是一篇地缘政治与产业调查报道，而非工程实践项目。但作为电子工程师或硬件开发者值得阅读的资料价值很高：稀土是永磁体、电机驱动、传感器等元器件的关键上游材料，了解供应链集中度风险、钍废料带来的监管约束以及海外多元化的进展，可以帮助工程师在元器件选型、BOM 替代方案和长期产品规划中更好地预判风险。总体而言，作为背景知识强烈推荐阅读，但不适合作为动手项目或学习案例。

**干啥的**: 这是 IEEE Spectrum 与《Foreign Policy》合作发表的地缘产业长文，聚焦独居石（monazite）这一具体矿种，探讨其能否成为西方国家挑战中国稀土垄断（约 90% 市场份额）的可行路径，并梳理了北美、澳新与欧洲的采矿、冶炼与政策布局。

**亮点**:
- 视角聚焦独居石这一具体矿种而非泛泛而谈稀土问题，给出了"为什么是独居石"的产业逻辑（富含钕、镨、镝等永磁关键元素）
- 覆盖北美、澳新、欧洲多地的项目与政策动向，可作为跟踪全球稀土去中国化进程的概览地图
- 引用自 1962 年起研究稀土的资深分析师 Jack Lifton 的判断（"The future is monazite"），具备行业权威性
- 明确点出稀土永磁体在电动车、机器人、国防装备等关键下游领域不可替代的战略地位

**我的判断**: 这是一篇偏宏观战略与产业政策的分析稿，对电子工程师的工程可操作性较弱——既没有可复刻的开源硬件项目，也不涉及具体器件选型或工艺参数。但作为产业背景读物，对理解钕铁硼磁体和稀土永磁电机上游供应链的风险图景有所帮助。复刻门槛：无需动手；适合人群：关注上游材料供应链与产业政策的工程师、产品经理与产业研究者，而非追求动手项目的硬件玩家。

### *（简报）* [DIY 热成像摄像头通过 WebUSB 直连浏览器](https://hackaday.com/2026/10/15/a-thermal-camera-that-uses-webusb/) ⭐️ 6.0/10 · 相关 7/10

**干啥的**：这是一个 Hackaday 上发布的 DIY 项目，作者做了一款热成像摄像头外设，它通过浏览器的 WebUSB API 直接与网页通信，省去了原本必须安装的配套手机 App；项目展示了在没有原生应用的情况下，如何仅靠一个网页就完成控制、数据查看甚至固件升级。

**亮点**：
- 用 WebUSB 把「浏览器」当成通用控制台，把外设的接入门槛从「下载安装 App」降到「打开一个网址」，这对小批量、爱好者向的硬件特别合适
- 针对当下 App 商店跨平台打包、签名、审核延期、强更等痛点提供了一个轻量替代方案
- 思路可复用：不光是热成像仪，任何自定义 USB 外设理论上都能套用这套「浏览器即驱动」的模式
- WebUSB 本身仍处于 Draft Community 阶段，但 Chromium 系浏览器已经支持，作者实际上是在押注这条正在成熟的路径

**我的判断**：这是一个值得一看但不必现在就动手复刻的项目。文档侧目前只放出了引言，原理图、固件、SDK 细节都还没放出，复刻门槛暂时无法评估。设计思路本身有亮点——尤其是 WebUSB 替代原生 App 的方向——对嵌入式工程师做设备控制前端时是个有价值的参考范式。适合人群：对 WebUSB、嵌入式 USB 协议栈、浏览器外设感兴趣的硬件/前端交叉开发者；对只需要一个能用的热成像仪的普通用户来说，直接买 FLIR 或 Seek 的成熟产品更划算。

### *（简报）* [自制 ESP32-S3 控制器结合 YOLO 视觉改造 Soonpho M7 云台](https://hackaday.com/2026/10/15/building-an-m7-pan-tilt-head-controller/) ⭐️ 6.0/10 · 相关 7/10

**干啥的**: 这是一个把消费级延时摄影云台 Soonpho M7 改造成实时运动追踪智能云台的 DIY 项目。作者用 ESP32-S3 微控制器加 NRF24L01 无线模块自制了替代原厂遥控器的控制器，配合一个自训练的 YOLO 视觉模型，让相机能自动跟踪画面中移动的目标。

**亮点**:
- 用 ESP32-S3 + NRF24L01 完全替换原厂遥控，把云台从「只能跑预设轨迹」升级到「可实时指令控制」，低成本但玩法大幅扩展
- 把重型视觉推理放在主机端 PC、实时电机执行放在 ESP32-S3，是嵌入式 + AI 协同的典型「重脑轻肢」分工思路，对机器人/自动化场景有借鉴价值
- YOLO 模型是自训练的，意味着只要换数据集就能改成跟人、跟车、跟动物，扩展性很强
- 整个 BOM 很轻量（M7 + 一块 ESP32-S3 开发板 + NRF24L01 模块），硬件门槛低，复刻友好

**我的判断**: 值得复刻，尤其动手的项目能从规模不大但系统完整：逆向了一个真实消费品的电机接口、搭了一条无线链路、把自定义 YOLO 流水线串到执行端，对练手来说含金量不错。文档方面目前只有 Hackaday 一篇正文，社区讨论也未提供，所以深度细节需要读者自己去看原文和作者的 BrothersFreedive 视频。门槛上需要具备基本的 ESP32 固件开发、串口/无线协议调试经验，以及能在 PC 端跑 YOLOv8 推理——对纯软件背景的人稍硬，但对硬件/嵌入式背景的工程师非常合适。整体上不算突破性技术，但作为「嵌入式 + 视觉 + 消费硬件逆向」三合一的小型综合项目，质量在 Hackaday 中属于中等偏上。

### *（简报）* [copper-rs 1.3 新增机器人 Profile Guided Scheduling 自动调度](https://www.reddit.com/r/robotics/comments/1x6y4nr/copperrs_13_new_autotune_your_robots_schedule/) ⭐️ 6.0/10 · 相关 4/10

**干啥的**：copper-rs 是一个面向自主机器人的开源 Rust 中间件框架，已被用于人形机器人、无人机、自动驾驶车辆等场景，内建确定性执行与日志回放。1.3 版本新增的 Profile Guided Scheduling（PGS）能从真实运行日志中自动搜索更优的任务调度计划，并在真实硬件上实测候选方案，最终离线编译进机器人 OS，无需开发者反复手动调参。

**亮点**：
- 把编译器 PGO 的"先采集、再特化"思路搬到实时任务调度上，自动适应目标频率与截止时间约束
- 调优过程完全离线运行，不引入任何运行时开销
- 在新增自动调度的同时，明确保留确定性执行与可回放这两项基石特性
- 已落地在多种真实机器人平台（人形、无人机、自动驾驶、AMR），具备实际工程基础而非停留在概念

**我的判断**：从项目质量看，copper-rs 的方向（Rust + 确定性 + 自动调度）非常契合当下具身智能/自主系统对安全与可调试性的需求，PGS 的设计把自动化与确定性这两个看似矛盾的目标做了不错的折中。但本次只是 1.x 小版本更新，文档与社区讨论都还比较单薄，复刻门槛主要在 Rust 实时生态与机器人中间件理解上，更适合做机器人/嵌入式方向二次开发或参考其调度思路，而非当作可复刻的硬件项目。对纯硬件开发者来说价值有限，但对做机器人系统软件或实时调优工具的人来说值得关注。

## [浏览器积木编程直接驱动 Arduino 机械眼睛](https://www.reddit.com/r/robotics/comments/1x6fmgr/i_built_animatronic_eyes_and_a_browser_app_to/) ⭐️ 5.0/10 · 相关 7/10

**干啥的**: 这是一个把硬件（Arduino UNO + 两个舵机 + 自设计的 3D 打印结构）和软件（浏览器内积木编程 + 模拟器 + WebSerial 直烧）整合在一起的电动机械眼睛项目，目标受众是从未写过代码的人，定位是未来的课堂教学工具。

**亮点**:
- 全流程零安装：编程、模拟、上传烧录全部在浏览器里完成，绕开 IDE、驱动和库的安装难题
- 自带模拟器：插上硬件之前就能在网页里预览眼球运动轨迹，降低试错成本
- 积木与 C++ 双向对应：每块积木都展示对应的一行 C++，并能导出标准 .ino 文件，便于从图形化过渡到文本编程
- 走 WebSerial 直连：相比 Arduino Cloud 之类方案，部署更轻、对学生机器更友好

**我的判断**: 作为硬件复刻项目，它目前不值得立刻动手——作者还没放出标准化的 BOM、固件和 3D 打印文件，属于早期原型阶段。作为软件参考价值更高：如果你正在做基于 WebSerial 的 MCU 上传工具链，或者想给国内中小学做一套零门槛的图形化烧录方案，这个项目的架构（积木 DSL → C++ → AVRDUDE/arduino-builder → WebSerial 写入）是一个不错的起点，可以等作者开源或自行重写后借鉴。适合做创客教育、教嵌入式入门的人关注，纯硬件党可以略过。

reddit · r/robotics · /u/tramlo890 · 10月15日 07:53

**背景**: Arduino UNO 是一款开源微控制器板，因工具链简单、外设生态丰富，被广泛用于教学和爱好者机器人项目。机械眼睛是一个常见的入门项目：一般用两个 SG90 级小舵机分别控制水平和垂直方向，配合 3D 打印支架即可搭建。WebSerial 是浏览器近年新增的 API，可以让网页在用户授权后直接与 USB 串口设备通信，从而无需本地工具链即可编译并烧录程序——思路与 Arduino Cloud Editor 或早期的 Codebender 类似。

**对中国影响**: 中国拥有非常活跃的 Arduino 创客和教育机器人社群，一个零安装的浏览器工具如果支持中文界面，确实能显著降低中小学和培训机构的上门门槛。但当前版本只有西班牙语界面、且仅支持 Chrome/Edge，在国内直接落地有限；不过其整体架构可以作为模板，被国内开发者 fork 后做汉化和适配。

**对我有什么用**: 对电子工程师来说，硬件参考价值一般——舵机云台和 3D 打印支架都是常规方案；但如果你打算做一个用于烧录 MCU 的浏览器工具链，那么 WebSerial 上传流程和积木到 C++ 的翻译逻辑值得研究。作为可复刻项目它目前得分偏低，因为还没有正式打包发布；现阶段更适合当作灵感来源，而非今天就能照搬的套件。

**入选理由**: 该项目完全符合读者对'可复刻开源硬件项目'的兴趣：基于 Arduino UNO + 3D 打印结构，浏览器内积木编程并通过 WebSerial 直接烧录，是典型的动手复刻项目；同时涉及嵌入式开发。但与 EDA、RISC-V、鸿蒙、AI 工具链等核心关注点不直接相关。
